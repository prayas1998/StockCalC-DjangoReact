## P1 — user-visible correctness and account integrity

- [ ] **Make journal trade and tag writes atomic and owner-validated.** `backend-node/src/routes/journal.ts:289-314,807-821,889-918` commits a trade update/create before replacing tags. The helper deletes old links before inserting new ones. A tagless create still performs a delete. A failed join write can leave the trade saved or its previous tags erased. Hono does not check supplied tag ownership before the write. Retrying create can duplicate the trade. The helper uses `trade`/`tag` (`:303-305`), while Django's declared relation fields are `trade`/`tag` and database columns are expected to include `_id` (`backend/journal/migrations/0001_initial.py:116-125`). Confirm the actual Supabase/PostgREST schema. Validate trade and tag ownership, use the actual relation column names, and persist trade plus tag replacement in one transaction/RPC. Test invalid and foreign tags, empty tags, concurrent replacements, and rollback on failure.
- [ ] **Use the caller's JWT/RLS scope on journal reads.** Authenticated list, detail, tag-list, and analytics reads use the anon `supabaseClient` without the caller’s JWT (`backend-node/src/routes/journal.ts:733-738,843-848,1047-1051,1335-1338`). Writes use `withUserScope`. With normal owner-only RLS these reads can return empty/denied results despite a valid user. Use the request JWT on every user-data read. Verify that each of two staging users sees only their own trades and tags.
- [ ] **Restore six unreachable GET endpoints.** In the locked Hono router, a dispatch fixture sent journal `analytics/`, `search/`, `suggestions/`, `tag_analytics/`, and `tag-analytics/` to the journal detail handler. It also sent `/api/tags/popular/` to tag detail. The parameter routes appear first in `backend-node/src/routes/journal.ts:835,1119`. Test that each named route reaches its own handler and numeric IDs still reach detail.
- [ ] **Honor current-password verification.** The schema requires `current_password`, but the password handler calls Supabase Admin to set `new_password` without checking the current password (`backend-node/src/routes/profile.ts:150-156`, `backend-node/src/validators/schemas.ts:39-45`). A stolen session can reset a password without re-authentication. Verify the current password with the authenticated user (or require recent re-authentication) before changing it. Test both incorrect and correct passwords. Account deletion also ignores the password sent by the UI (`frontend/src/services/profileApi.ts:112`, `backend-node/src/routes/profile.ts:181–188`). Verify that failed reauthentication leaves the account intact.
### Trading calculations and UI

- [ ] **Correct short-position sizing fees.** The position-sizing service passes entry/stop notionals in long order for short trades (`frontend/src/services/calculators/PositionSizingCalculatorService.ts:227-235`). STT/stamp duty can be computed from the wrong leg. Calculate short charges using the actual sell-then-cover legs and test both long and short against known fee fixtures.
- [ ] **Correct the multi-leg short breakeven.** `backend-node/src/calculations/equityIntraday.ts:139-146` takes the first leg's price as the short entry. Reversing two short legs preserves net P&L but changes the quoted breakeven from ₹99.87 to ₹199.79 for two Dhan NSE shorts (10 shares sold at ₹100 and covered at ₹90, another 10 sold at ₹200 and covered at ₹180). Both yield ₹296.76 net. Under the current fee model a common cover at ₹149.83 nets +₹0.04 and ₹149.84 nets −₹0.16. Compute the weighted/aggregate short entry from all legs and verify leg-order invariance and the adjacent non-loss/loss prices.
- [ ] **Reconcile low-notional breakeven with fees.** `backend-node/src/calculations/breakevenCalculator.ts:29-56,118-161` searches only a bounded price grid and applies a one-paisa adjustment. A Dhan one-share delivery buy at ₹1 is quoted at ₹5 breakeven while still losing ₹10.75. A separate Groww BSE intraday fixture with two distinct one-share buy orders at ₹200 quotes ₹205.92, but one two-share exit there loses ₹5.90. The fixed upper bound clips the Dhan result. The Groww solver combines buy orders and loses one brokerage minimum. Replaying the exits gives zero at ₹15.75 and ₹208.87 respectively under the current fee model. Compare the returned price against independently recomputed final net P&L across tiny notional values, multiple orders, and broker/exchange cases. Return the first eligible non-loss exit tick for a long, the highest for a short, or explain when none is reachable.
- [ ] **Separate realized P&L from open-position cash flow.** Delivery and intraday calculators calculate gross as all sell proceeds less all buy costs (`backend-node/src/calculations/equityDelivery.ts:77-78`, `backend-node/src/calculations/equityIntraday.ts:89–90`). A buy of 10 at ₹100 followed by a sell of 5 at ₹110 reports −₹450 despite +₹50 realized and 5 shares still open. Calculate realized P&L from matched quantity and show remaining open quantity/cash flow separately. Cover opening-only, fully closed, and partial long/short trades.
- [ ] **Calculate STT on matched NSE intraday turnover.** `backend-node/src/calculations/equityIntraday.ts:70` applies STT to raw sell turnover rather than matched quantity × matched VWAP for netted NSE positions. A 100-share buy at ₹98 and sell at ₹101 reports ₹3 vs ₹2 after nearest-rupee rounding for an isolated trade (raw ₹2.525 vs ₹2.4875). The sell-only basis can change the final rupee even on a fully closed trade. Net by instrument and trading day before applying the published methodology and rounding. Test unmatched lots and multiple prices. Use [Groww's STT explanation](https://groww.in/blog/how-is-stt-levied) and [NSE circular CMTR5588](https://nsearchives.nseindia.com/content/circulars/cmtr5588.htm) for methodology, and current broker tariffs for rates.
- [ ] **Correct Groww small-order brokerage.** In Chrome, one Groww NSE intraday share sold and covered at ₹100 showed ₹10 brokerage and −₹11.81 net. The 2.5% cap at this order value gives ₹2.50 per side, or ₹5 total. Test just below, at, and above ₹200 per order against both the API and Tools. See `backend-node/src/calculations/index.ts:161–170` and `frontend/src/pages/Tools/ChargesUtils.ts:53`. [Groww brokerage rule](https://groww.in/help/stocks/sx-pricing/what-are-intraday-charges)
- [ ] **Count applicable delivery debits.** The API applies Groww ₹21.54 once per request. At sell values ≥₹100, Groww’s standard and female depository rates produce ₹23.60 and ₹23.31 including GST. Below ₹100 the corresponding totals are ₹4.13 and ₹3.84. Dhan’s ₹14.75 is correct for one applicable debit instruction. Test one order with several fills and two separately chargeable debits. Identify the order/account assumptions in the UI. See `backend-node/src/calculations/index.ts:176` and `backend-node/src/calculations/equityDelivery.ts:53`. [Groww DP tariff](https://groww.in/help/stocks/searchable/when-are-dp-charges-levied), [Groww order examples](https://groww.in/help/stocks/searchable/are-dp-charges-per-stock-or-per-order), [Dhan pricing](https://dhan.co/pricing/)
- [ ] **Qualify exchange fees by scrip group and tariff date.** At ₹20,000 BSE turnover, the default fee is ₹0.75 while an X-group scrip costs ₹20. Identify eligible scrips or state that only standard-group fees are estimated. For ₹1 crore NSE turnover, the code reports ₹297 exchange fees and ₹10 IPFT. Dhan publishes ₹306.99 and ₹0.01, with the same combined amount. Groww’s pricing and help pages disagree on the split. Verify its allocation against a dated, redacted note. See `backend-node/src/calculations/index.ts:218–243,257–282`. [Dhan pricing](https://dhan.co/pricing/), [Groww pricing](https://groww.in/pricing), [Groww fee details](https://groww.in/help/stocks/sx-pricing/what-are-intraday-charges), [NSE revision](https://nsearchives.nseindia.com/content/circulars/FA73061.pdf)
- [ ] **Reject invalid calculation inputs.** `backend-node/src/validators/schemas.ts:4-28` accepts negative/fractional quantity and arbitrary exchange strings. `delivery + SHORT` is also accepted. In the reviewed fixtures, negative quantity produces negative fees and quantity `0.5` displays as zero. Reject nonpositive/nonintegral quantities, unsupported exchanges, and unsupported trade/position combinations while preserving valid one-sided transactions. Test each rejected case and valid boundary. In the position-sizing UI, selecting Intraday → Short → Delivery hides the side selector while retaining Short. Reset it on the transition and test the resulting delivery estimate (`frontend/src/components/calculators/PositionSizingCalculatorContainer.tsx:23`, `frontend/src/components/shared/BrokerTradeTypeSelector.tsx:73`).
### Account and journal behavior

- [ ] **Keep login identity consistent when a username changes.** Username login is mapped to a synthetic email (`frontend/src/lib/authIdentity.ts:1-18`, `frontend/src/context/AuthContext.tsx:184-190`), while profile username updates change auth metadata only (`AuthContext.tsx:234-257`). The new username may not resolve to the account's login email. Keep the login mapping consistent with a rename or explicitly make usernames immutable. Test login with old/new identifiers. If email confirmation is enabled, verify how a new user can confirm a synthetic .local address.
- [ ] **Clear stale calculator results when inputs are cleared or recalculated.** In Chrome, clearing the Dhan example zeroed all three inputs but left ₹6 turnover, ₹14.75 charges and −₹10.75 net on screen (`frontend/src/components/calculator/TransactionForm.tsx:58`, `frontend/src/hooks/useCalculation.tsx:197-206`). Results no longer correspond to visible inputs. Delayed calculation responses can restore stale output. Clear the result together with the inputs. Test a delayed response after Clear and after a newer calculation.
- [ ] **Preserve valid journal filters in the URL and on page load.** `useJournalFilters` parses/syncs status, type, dates, tags, profitability, and query but omits `companies` (`frontend/src/hooks/useJournalFilters.ts:11-77`). `JournalPage` hydrates selected companies from that hook (`frontend/src/pages/JournalPage.tsx:68-87`). The company filter disappears on refresh or URL sharing. The page also reads search text from separate local state, discarding the query restored by the URL hook (`JournalPage.tsx:23–47`). Parse and serialize company filters and restore search text and confirm refresh, back/forward, and shared-URL behavior.
- [ ] **Validate PATCH target/stop relationships.** Update schema accepts these persisted fields but does not cross-validate a partial payload against the existing trade's entry price/direction (`backend-node/src/validators/schemas.ts:127-151`). A partial edit can leave an invalid target/stop relation. Validate merged old+new trade state and cover valid partial updates plus invalid direction/entry combinations without partial mutation.

## P2 — availability, lifecycle, and verification

- [ ] **Make the configured rate limiter count requests.** `backend-node/src/middleware/rateLimit.ts:9-18` prunes timestamps but never appends the current request, so the count stays zero. Configured limits never trigger. Record accepted requests and test the configured limit, window expiry, and enforcement across deployed instances.
- [ ] **Verify account deletion removes user-owned records.** Deployment-dependent. `backend-node/src/routes/profile.ts:181-203` deletes the Supabase auth user and assumes related data disappears. The declared Django ownership columns are plain UUIDs. Django explicitly removes trades and tags (`backend/calculator/views/profile_views.py:198–208`). Without equivalent cleanup or a database cascade, Hono can leave personal data behind. Inspect deployed constraints and run deletion in a dedicated synthetic staging project, confirming all owned rows are removed and the second fixture user’s rows survive (or implement retry-safe cleanup).
- [ ] **Scope analytics reads and avoid silent truncation.** Analytics reads are unpaged (`backend-node/src/routes/journal.ts:1335-1353,1406-1417`). Accounts larger than the deployed PostgREST row cap get incomplete analytics. Verify the deployed cap and test an account above it. Paginate/aggregate until all rows contribute.
- [ ] **Return the expected authentication error on unauthenticated journal reads.** A signed-out local GET to `/api/journal/` returned HTTP 500. The route throws on missing authentication (`backend-node/src/middleware/auth.ts:109–113`). The UI cannot distinguish a missing session from an internal error using this status. Return the intended 401 JSON response. Check owner success and missing-record responses separately.
- [ ] **Report session revocation failures accurately.** Hono returns success after Supabase rejects a revoke request. Its fallback calls a method absent from the locked SDK. The security-status endpoint separately reports zero sessions when enumeration is unavailable (`backend-node/src/routes/auth.ts:67–87,167–175`). Exercise provider success, rejection, and unavailable session counts. Display an unknown count when enumeration fails.
- [ ] **Make validation commands give meaningful release signals.** With locked dependencies on Node 24.21, backend `npm test` exits 0 with zero tests. Backend lint exits 2 because its config is missing. Frontend build succeeds, lint reports 11 warnings, `tsc -p tsconfig.app.json --noEmit` exits 2 on TypeScript diagnostics, while root `tsc --noEmit` silently skips the app sources. Release checks can pass without testing the actual frontend code or fail for configuration/diagnostics without a clear gate. Add regression coverage for critical API/calculation behavior, repair lint/type-check entrypoints, and document/run locked install and CI checks (`npm ci`, app typecheck, lint, tests, build) with meaningful clean exit codes.
